# Probe v0.5.0

SwiftProof is now **Probe**. This release changes names only; the analysis, the
report schema and the exit codes are those of v0.4.17. Every name below changes
together, so a workflow pinned to an earlier release keeps working with that
release and needs the steps under "Upgrading" to move to this one.

## Renamed

- The binary is `probe` (`probe.exe` on Windows) and the archives are
  `probe-<version>-<os>-<arch>`.
- The repository policy file is `.probe.json`. `.swiftproof.json` is no longer
  read.
- The output directory is `.probe/` (`.probe/CONFIDENCE_REPORT.md`,
  `.probe/confidence-report.json`, ...).
- Environment variables start with `PROBE_` (`PROBE_API_KEY`,
  `PROBE_REVIEWER_ENDPOINT`, `PROBE_HUB_*`, ...) instead of `SWIFTPROOF_`.
- The Go modules are `github.com/gvinsot/Probe/app` and
  `github.com/gvinsot/Probe/hub`; the hub binary is `probe-hub`.
- The website and the hub are served on `probe.technology` and
  `app.probe.technology`.

## Upgrading

1. Rename `.swiftproof.json` to `.probe.json` on the base branch.
2. Rename the `SWIFTPROOF_*` variables and secrets your CI and deployment pass
   to `PROBE_*`.
3. Re-pin workflows to the `probe-v0.5.0-<os>-<arch>` archive (URL and sha256
   together, as in [CI integration](https://github.com/gvinsot/Probe/blob/v0.5.0/app/docs/CI.md)).
4. In the hub, register the OAuth callbacks
   `https://app.probe.technology/auth/github/callback` and
   `https://app.probe.technology/auth/gitlab/callback`.

## Consequences to expect

- The execution cache key and the fuzz seed derive from the tool name, so
  existing cache entries are not reused and generated fuzz inputs differ.
- The SARIF `partialFingerprints` key is now `probe/v1` with new values, so code
  scanning treats existing alerts as new ones.
